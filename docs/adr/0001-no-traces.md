# Traces are disabled end-to-end in production

The POC captured all three OTel signals; `spans` was the fattest table and its only report use (per-tool counts/duration/errors) is equally derivable from `tool_result` events. In production we disable traces at the source (`OTEL_TRACES_EXPORTER=none`), drop the traces pipeline from the collector, and omit trace parsing and the `spans` table from the sink and schema-v2. Deliberately forfeited: per-API-attempt detail (`ttft_ms`, retries) and the subagent parent/child hierarchy (`agent_id`/`parent_agent_id`), which exist only in spans — the adoption report needs subagent usage *counts* (available from events), not the spawn tree. With traces off at the source, none reach the blob raw reservoir either (ADR-0005): uncaptured trace data is gone forever. Revisit only if a future KPI genuinely needs latency or agent-tree analysis.
